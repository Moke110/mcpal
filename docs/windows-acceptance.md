# Windows 便携版与联合验收

解压整个 ZIP，双击 `MC-Pal.exe`。首次启动进入「模拟模式」，可直接询问「附近有谁？」、跟随「小明」、改跟「小雨」及停止。请保留与程序同目录的运行时文件。程序无需另装 Node.js。

## 本机设置

从窗口中的「联合验收」打开本机设置目录。将解压目录内的 `settings.example.env` 另存为设置目录下的 `.env`，只填需要的项目，保存后关闭并重新打开应用。凭据保存在本机设置目录。

- Minecraft 使用「Minecraft 实机」填写 Java 地址、端口、账号与授权玩家。Microsoft 登录时按设备授权提示操作。验证机器玩家身份、昵称、第一人称画面、换维度及清除旧画面。桌面 PNG 预览仅在本地显示。
- API 配置 `MCPAL_API_BASE_URL`、`MCPAL_API_KEY` 和 `MCPAL_API_MODEL`。先运行连接测试，再选择该后端。允许向供应方发送真实观测和游戏聊天时单独勾选实机选项。
- 本地后端配置可用 CUDA 的 Windows `llama-server.exe` 和 GGUF 的绝对路径。选中后端后手动启动并预热。
- CPU ASR 需要装有 Vosk 的 Python 和普通话模型。设置 `MCPAL_ASR_MODEL`，如需指定解释器则设置 `MCPAL_ASR_PYTHON`。在界面选择输入设备后启用麦克风。CPU TTS 使用已安装的 Windows 普通话桌面语音，在界面选择输出设备并试听。

## 现场验收记录

使用同一个已授权游戏环境，按顺序分别从 GUI、`!pal <请求>` 和本机 ASR 输入。在 GUI 核对内容，按需明确开启游戏公开发言及 CPU TTS。受信聊天可以发送 `!pal 跟随我`，由机器玩家跟随该消息的发送者。GUI 和语音请求需写明目标玩家。每次重连确认公开发言恢复关闭。

对 API 和本地后端使用同组请求。「我在哪？」核对观测，「跟随 A」确认机器玩家实际移动，「改跟 B」核对旧跟随清理后再跟随 B，「停止」核对任务终止、控制释放和移动停止。记录每条请求的来源、后端、是否提交、是否过期、取消和实际动作。A、B 使用当前可观测的玩家名。确认退出时已断开游戏并回收本地进程。

核对本地后端在冷启动、预热和连续交互中的逐进程显存数据。记录模型、运行时、驱动、上下文、GPU 层数、采样数、最大采样间隔、独显及共享显存峰值。真实独显峰值须严格低于 6,000,000,000 字节。界面显示的 WDDM 采样值只能证明观测到的峰值。

使用同一时基分别记录语音结束估计、语音最终文本、窗口关闭、完整校验和动作提交。首段可听时间以实际音频输出确认，停播使用实际最后呈现帧，停止使用控制释放和实际移动终止。播放含「停止」的句子时保持安静，确认跟随继续；再测试同时说话的插话停播和明确停止。
