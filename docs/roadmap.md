# 路线图

## M1 无头连接与结构化观测

- [x] 建立 TypeScript 项目、配置、依赖锁和运行脚本。
- [x] 在 `1.21.11` 和 `26.1` 的隔离回环协议测试中，走通自动版本检测、独立登录、出生、结构化状态读取和断线。
- [x] 在房主开放的 `26.1` 局域网世界中以独立离线玩家进服，确认真人玩家同服并读取真实区块、空背包和附近实体数据。
- [x] 在 `26.1` 局域网世界中验证真人移动时，观测快照随之更新，并在真人离开和返回观测范围时移除和重新列出该玩家。
- [x] 从终端按需读取状态。在真实 `26.1` 局域网存档上实测了 `status` 与正常退出。
- [ ] 完成 Microsoft 设备授权及正版账号端到端联调。

2026-11-21 的局域网状态查询确认房主世界可达，报告 Java 版 `26.3`（协议 `777`）和一名在线玩家。锁定的 Mineflayer `4.39.0` 和 `minecraft-protocol` `1.68.0` 最高声明支持 `26.1`。`minecraft-data` `3.119.0` 能识别 `26.3` 的版本号，但无法加载该版本的游戏数据。该世界尚未执行登录或快照验收。[上游 26.3 协议与数据变更](https://github.com/PrismarineJS/minecraft-data/pull/1301)

房主改用 `26.1` 后，状态查询确认该局域网世界可达，报告协议 `775`。离线玩家 `Companion` 成功登录并输出两条快照。首次快照中的方块为 `null`，后续快照读到了草方块、藤蔓、约 4.47 格外的真人玩家及一只僵尸。真人世界里的背包为空，非空背包解析已在回环测试中覆盖。采样后客户端正常断开。

真人往返测试以每秒一条快照采样。`Companion` 保持原位，快照读到真人玩家的位置和距离随移动变化。离开前最后一条可见记录距离为 30.35 格，随后连续 10 条快照的 `nearby.players` 为空。返回后的第一条记录距离为 20.02 格，继续靠近时更新为 2.95 格。

## 桌面伙伴一期

首个可运行交付是 Electron 模拟场景。之后每张工单都通过同一 GUI 提供可复核结果。[一期规格](https://github.com/Moke110/mcpal/issues/8)

| 里程碑 | 工单 | GUI 验收 |
| --- | --- | --- |
| 1. 模拟桌面 | [#9 模拟 GUI](https://github.com/Moke110/mcpal/issues/9) | 无需配置游戏、模型和音频即可发消息、改口、停止，并观察超时和清理状态。 |
| 2. 会话调度 | [#11 自适应窗口](https://github.com/Moke110/mcpal/issues/11) | 查看窗口和迟到结果，验证下一窗口提交、取消及过期。按后端实测的完整可校验结果耗时调整未来窗口。 |
| 3. 游戏接入 | [#10 Java 与 LAN 连接](https://github.com/Moke110/mcpal/issues/10)、[#12 Minecraft 聊天](https://github.com/Moke110/mcpal/issues/12)、[#13 第一人称视角与外观](https://github.com/Moke110/mcpal/issues/13) | 连接游戏，从受信聊天发送请求、按显式路由回复，查看身份设置与机器人视角。 |
| 4. 模型后端 | [#14 API 后端](https://github.com/Moke110/mcpal/issues/14)、[#15 本地后端与显存](https://github.com/Moke110/mcpal/issues/15) | 切换后端并运行相同场景。本地主模型实际推理峰值严格低于 6,000,000,000 字节。 |
| 5. 本机音频 | [#16 CPU TTS](https://github.com/Moke110/mcpal/issues/16)、[#17 按键录音与 CPU ASR](https://github.com/Moke110/mcpal/issues/17)、[#18 开放麦与回声消除](https://github.com/Moke110/mcpal/issues/18) | 选择设备，查看转写，试听、插话并观察实际停播。验证旧播报的回声不会触发游戏动作。 |
| 6. 联合交付 | [#19 Windows 打包与联合验收](https://github.com/Moke110/mcpal/issues/19) | 在打包应用中验收三个入口、三个出口和两个后端，确认状态追问、跟随、改口及停止，查看实测或故障。 |

上一版语音链路的 P95 参照值为说完到首段可听回复 ≤ 800 毫秒，说完指令到提交动作 ≤ 700 毫秒，开始插话到实际停播 ≤ 250 毫秒，说完停止指令到旧任务终止 ≤ 500 毫秒。本期分别记录 ASR 最终文本、关闭读取窗口、读取完整结果、动作提交、实际播报和游戏任务终止等时间点，并报告 P95、超时与取消。窗口长度和后端表现以本期实测为准。[一期桌面设计](architecture.md#一期桌面设计)
